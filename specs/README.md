# 功能规格

这里保存需要跨越多个模板、配置、内容模型或部署边界的功能规格。

普通文章、单个样式调整和单文件修复不需要创建 Spec。只有当任务需要拆分实施、明确验收条件，或需要在会话之间交接时，才创建：

```text
specs/001-short-name/
├── spec.md       # 目标、范围和不做什么
├── plan.md       # 实现顺序和依赖
├── tasks.md      # 可执行任务与完成状态
└── contract.md   # 需要保持的内容、路由或模板契约
```

目录编号按创建顺序递增。完成后在 `.handoff/` 记录最终验证边界，并在 `docs/architecture.md` 或相关 ADR 中补充长期有效的事实；不要把一次性过程状态复制到架构文档。
