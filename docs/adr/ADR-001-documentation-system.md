# ADR-001：采用分层的项目文档机制

- 状态：Accepted
- 范围：项目文档与 Agent 上下文管理

## 背景

项目同时需要服务人类写作和 Agent 接管。把所有说明放在 README 或单个 Agent 文件中，会让入口变长，也会把稳定规则、架构事实和临时工作状态混在一起。

## 决策

采用以下分层：

1. `AGENTS.md` 只保存稳定执行协议和读取顺序；
2. `docs/architecture.md` 保存当前目录边界、内容契约、渲染链路和任务路由；
3. `docs/blog-usage.md` 保存普通作者的操作步骤；
4. `docs/adr/` 只保存会影响未来修改的长期决策；
5. `.handoff/latest.md` 指向最新工作上下文，日期文件保存一次交接的具体状态；
6. `specs/<id>/` 只为跨多个边界且需要验收标准的功能启用。

## 结果

- Agent 可以先读取短入口，再按任务路由加载必要上下文。
- 历史决策、当前事实和临时状态分开，减少把旧信息当成当前事实的风险。
- 文档层级增加了维护责任；改变架构或目录时必须同步更新架构文档和相关 handoff。
